# Clean-machine install checklist

Run this on a machine (or a fresh user account) that has never had System Budget Studio, with no administrator rights and, ideally, no network. Tick each line; the sign-off at the end is the M6 acceptance for installation.

`CI` marks steps that the **Installers** workflow (`.github/workflows/release.yml`) already runs on every change to `packaging/` and on every tag; a person still has to do the steps that need a screen.

## Windows 10 or 11 (standard user)

- [ ] Run `system-budget-studio-<version>-windows-x64-setup.exe` as a standard user: no elevation prompt appears; it installs to `%LOCALAPPDATA%\Programs\System Budget Studio`; it asks no question except the folder, and needs no Python. (CI: silent install with `/CURRENTUSER`.)
- [ ] The Start menu has *System Budget Studio*; it starts and shows the window in the Inter font (text) and JetBrains Mono (numbers). (Manual.)
- [ ] `budget --version` and `budget self-test` pass in a new terminal (the setup has added its folder to your PATH; no question is asked). (CI.)
- [ ] File > New project (guided): finish with the defaults; the first power timeline appears. (Manual; the automated wizard test covers the logic.)
- [ ] File > Export reports writes XLSX, PDF and DOCX that open in Excel, a PDF reader and Word. (Manual.)
- [ ] With the network cable out or Wi-Fi off, everything above still works. (Manual; the offline test covers the code.)
- [ ] Uninstall from *Apps and features*: the program folder, the Start menu entry and the PATH entry are gone (check *Environment Variables* for your user), your project folder is untouched. (CI: silent uninstall and the PATH entry.)
- [ ] The portable zip starts from a USB stick or a folder, installs nothing and makes no registry entry; the only file the window writes outside it is `layout.ini` in `%APPDATA%\System Budget Studio\`, and nothing at all with `BUDGET_NO_LAYOUT=1`. (Manual.)

## RHEL or Rocky Linux 9 (ordinary user)

- [ ] `tar xzf` the bundle and run `./install.sh` without sudo: it installs to `~/.local/opt/system-budget-studio` and prints *Self-test passed.* (CI: in a rockylinux:9 container as an unprivileged user.)
- [ ] The window starts on a graphical session (X11 or Wayland with XWayland) and shows the window in the system's colour scheme (light or dark; *View > Theme* switches it live). (Manual: needs the desktop libraries listed in the guide.)
- [ ] `budget run`, `budget power-timeline` and `budget compare` on the example projects write their files. (Manual; the CI runs `budget self-test`.)
- [ ] `~/.local/opt/system-budget-studio/uninstall.sh` removes the program, the links and the menu entry. (CI.)

## Ubuntu LTS (ordinary user)

- [ ] The same bundle installs and passes the self-test. (CI: ubuntu-latest, no sudo for the install.)
- [ ] The window starts and the guided wizard completes. (Manual.)

## Ubuntu or Debian, with the .deb (administrator)

- [ ] `sudo apt install ./system-budget-studio_<version>-1_amd64.deb` installs the package and the libraries it needs; `budget --version` and `budget self-test` pass. (CI: Ubuntu 22.04 and 24.04 and Debian 12 containers, as root.)
- [ ] The menu entry *System Budget Studio* is there with the logo as its icon; the window starts from it and shows the logo in the title bar and the task bar. (Manual; CI starts the window on a virtual X server.)
- [ ] `sudo apt remove system-budget-studio` takes away `/opt/system-budget-studio`, the two links in `/usr/bin`, the menu entry and the icons; your project folders are untouched. (CI.)

## RHEL or Rocky 9, with the .rpm (administrator)

- [ ] `sudo dnf install epel-release`, then `sudo dnf install ./system-budget-studio-<version>-1.x86_64.rpm` installs the package and the libraries it needs (`xcb-util-cursor` comes from EPEL); `budget --version` and `budget self-test` pass. (CI: a rockylinux:9 container, as root.)
- [ ] The menu entry is there with the logo, and the window starts from it. (Manual; CI starts the window on a virtual X server.)
- [ ] `sudo dnf remove system-budget-studio` takes away everything the package installed. (CI.)

## The window, on a real screen (new in 1.1.0, redone for 1.2.0; Windows, Rocky 9 and Ubuntu)

The window (redesigned in 1.1.0 and 1.2.0) was built and tested on a virtual (offscreen) display, which has a pixel ratio of 1. These steps need a person at a real screen; at least one of them on a 4K or 200 % display.

- [ ] With no project open the **welcome page** shows *Open a project folder…* and *New project (guided)…*; dropping the example folder on the window opens it. (Manual.)
- [ ] Open the complete 250 kg example. The project tree is quiet (one row per unit, badges only for errors and warnings). The text in the tree, the grids, the Problems panel (one line of counts in the focused view the window starts in; **Show problems** opens the list) and the top bar is sharp and not too small at 200 %; nothing is cut off or overlaps at 1280 x 720. (Manual; UX-47.)
- [ ] **Model > Power modes**: change a number, Ctrl+Z undoes it, a wrong value is explained under the grid, **Save** writes the file and keeps its comments. (Manual.)
- [ ] **A blank project** (1.4.0): **File > New project (guided)**, pick *Blank project*, give a bus voltage, **Finish**: the project opens on **Model > Units** with no unit, and the Problems panel lists the placeholders (**Show problems** in the focused view). **Add unit** (button, **Ctrl+Shift+N** or Ctrl+K) opens a form (Tab walks through every field, nothing is cut off at 200 %): the new unit is in the grid, **Save** writes its file, **Remove unit** then **Save** asks before it deletes the file, and **Undo** brings a removed unit back. **Add spacecraft mode** (**Ctrl+Shift+M**) opens a form, the new mode is in **Model > Spacecraft modes** with a row per unit, a typed power mode the unit does not have is refused with a message, and **Remove spacecraft mode** is refused while a scenario names the mode. **Add scenario** (**Ctrl+Shift+O**, or the button on the empty *Model > Scenario* page) opens a form that takes no default number; after **Save** and **Run** the first timeline shows eclipses. (Manual; the automated tests cover the logic.)
- [ ] **Start here and the focused view** (1.5.0, first-run pass 1.5.1, forms and single click 1.6.0): a new project shows the **Start here** card under the top bar with four steps (*Unit*, *Spacecraft mode*, *Orbit and scenario*, *Save and run*); its blue button does the step to do now, a step that needs an earlier one is greyed with a tooltip that says which, the card goes when all four are done, the **×** hides it for good (restart and check) and **Help > Start here** brings it back. A first start (no saved layout, or **View > Reset layout**) is the **focused view**: the Problems panel is one line of counts with a *Show problems* button, the Inspector and Provenance panels are hidden and a grid with optional columns has an *Optional columns* button. **View > Focused view** (**Ctrl+Shift+F**) turns it off for the full window and back; the *not checked* link in the status bar and **F8** open the list. **Edit > Add expendable** (Ctrl+Shift+X): the form has one mass field per mission phase of the project, refuses an empty one and a position with fewer than three coordinates, and the second expendable appears in the project tree and in the Mass area after **Save** and **Run**. **Edit > Add ground station** (Ctrl+Shift+G) and **Add imaging target** (Ctrl+Shift+T): the Add button stays off until the name, the id and the four numbers are right, an id used by the other kind is refused, and after **Save** the file is in `ground_stations/` or `targets/` and the project tree. **Edit > Remove from project** (Ctrl+Shift+R): in the example, an expendable and a link can be removed (**Save** asks before it deletes the files, and **Undo** before that brings them back), a ground station and the imaging target are refused with the scenario and the link that name them; remove the link and take the site out of the scenario and the station can go. **Edit > Add Eb/N0 entry** (Ctrl+Shift+B): the form takes a modulation and a coding, refuses a pair the table has already (also in other capitals), and after **Save** the new row shows a placeholder in **Model > Inputs**; the link form then offers the pair. **Edit > Add link** (Ctrl+Shift+L): in a project without a ground station the status line says to add one first; with one, the form offers the stations and, in the example, the pairs of the Eb/N0 table, refuses a frequency typed in hertz and a data rate that is not a number, and after **Save** the new link shows placeholder rows in **Model > Inputs** and *n/a* in the Link area. **Edit > Add scenario**: a length of 180 days is accepted (181 is refused), the *Apogee altitude* field is empty for a near-circular orbit and, once filled, enables *Argument of perigee* and the first run shows eclipses that fit an elliptical orbit. With **View > Open with a single click** on (and in the Settings card), a click on a node of the project tree opens it and a click on a selected grid cell edits it; off, only a double-click or Enter opens and a double-click, F2 or typing edits; restart: the choice is kept. In **Model > Spacecraft modes**, double-click (or F2 on) a *power mode* cell: a list of that unit's power modes opens, one click chooses it and the file shows the change after **Save**. A blank project opens on the **Model** area (Units grid) with the rail naming *Model*; a project with units opens on **Power** with the rail naming *Power*. **Save and run** of the card ends on **Power → Timeline** with a toast. A focused tab (click *Model*, then look at *Units*) shows one ring, not a ring and a second outline over the label. The **BOL / EOL** control in the top bar is one pill with one ring when it has the keyboard, at 100 % and at 125 %. Nothing is cut off on a short screen (a laptop at 1366 x 768). (Manual.)
- [ ] **Add Eb/N0 entry and Remove from project** (1.7.0): **Edit > Add Eb/N0 entry** (Ctrl+Shift+B) adds a pair with a placeholder, **Edit > Add link** then offers it; **Edit > Remove from project** (Ctrl+Shift+R) refuses a ground station that a scenario or a link still names, removes an unused one, **Ctrl+Z** brings it back, and **Save** asks before it deletes the file. (Manual.)
- [ ] **Explain and the rule of a problem** (1.8.0): open the 250 kg example, go to **Power**, select a *With margin (W)* value, press **Ctrl+Shift+I** (or right-click the value, *Explain this value*): the **Explain** panel opens on the right with the equation, the inputs with the file each came from and the steps. The same on a **Mass**, **Thermal** and **Link** table. Select a problem in the Problems panel (turn **View > Focused view** off): its rule, why it matters and what to do appear under the list. In a terminal: `budget explain <project> power:units:nominal --row <unit> --column "With margin (W)"` and `budget problems MASS_LIMIT_EXCEEDED`. (Manual; tests check the panel and the texts.)
- [ ] **Explain on the timeline and the link passes, and the save and run notices** (1.9.0): open the 250 kg example, run it, go to **Power > Timeline**, select a *Lowest SoC (%)* value in the Summary table and press **Ctrl+Shift+I**: the Explain panel says it is preparing the explanation, then shows the stored energy at the lowest point with its equation and inputs. On **Link > Passes** select a *Lowest margin (dB)* value: the whole link budget at that sample appears. In **Model > Units** change a power, do **not** save, and press **Run**: the status bar says the run is on the saved files and the chip says **Out of date**. (Manual; tests cover the panel, the chip and the texts.)
- [ ] **Sources, the Assumptions page and the model choices** (2.0.0): open the 250 kg example, select a power in **Model > Units**: the **Inspector** (turn **View > Focused view** off) has a *Source* field; type a source, press *Set source*, press **Ctrl+Z** (the source goes), redo, and save. Open **View > Show the assumptions** (**Ctrl+Shift+A**): the list has four kinds of rows, the filter keeps the rows with every word typed, and a double-click on a row that names a file opens it at the field. In **Model > Scenario** choose *Earth constants* = `wgs72` and *Irradiance on the array* = `seasonal`: **Save**, check that `project.yaml` now lists `model_choices` under `requires:`, run, and see the rows *Earth model* and *Irradiance model* in the provenance of an exported report. In a terminal: `budget choices`, `budget assumptions <project>`, `budget source <project>`. (Manual; tests cover the panel, the editor and the texts.)
- [ ] **Scenario time span, statistics and the new words** (2.1.0): open the 250 kg example, go to **Model > Scenario**: the start, the duration and the step are fields at the top; change the duration, **Ctrl+Z** takes it back, type a step longer than the duration and see the problem under the editor. Press **Compute**: the **Statistics** tab has the eclipse figures above a table with a row per station and target (passes, contact time, shortest, mean and longest pass, largest gap, elevations); the **Passes** tab has a *Passes of* drop-down. **Model > Power modes** and **Spacecraft modes** each show a line saying what their mode is and buttons *Add power mode* / *Add spacecraft mode*; hover the **mass_kg** and **bus** headers of **Model > Units** for their hints. **Edit > Add Eb/N0 entry** (Ctrl+Shift+B) has optional bit and frame error rate fields. (Manual; tests cover the tabs, the fields and the texts.)
- [ ] **Orbit helper, beta angle, ground track and the new budgets** (2.2.0): open the 250 kg example. **Edit > Orbit helper...** (Ctrl+Shift+H): choose *Sun-synchronous* with an altitude and a local time, the inclination and RAAN appear; *Write to orbit* then **Ctrl+Z** undoes it in one step. Go to **Model > Scenario**, **Compute**: the tabs **Beta angle** and **Ground track** show a plot and a graticule map with the two stations and the target marked; the **Statistics** tab has the beta and latitude lines. In a terminal: `budget run <project> --budget propulsion` and `--budget pointing` write a report each; open the XLSX of one in a spreadsheet program. `budget tables-export <project> ebn0 --out t.xlsx` opens in a spreadsheet program, and a value typed without a source is refused by `tables-import`. (Manual.)
- [ ] **Pointing, burns and the new pages** (2.3.0): open the 250 kg example. The **Mass** area has a *Propulsion* page and the **Power** area a *Pointing* page with tables. Go to **Model > Scenario**: the *Pointing* section has a default pointing mode (choose *nadir*), then **Add pointing rule** (an eclipse rule to *target*), and the *Manoeuvres* section has **Add manoeuvre** (an electric manoeuvre needs a system with power; edit `config/propulsion.yaml` to try it). **Compute** and open **Power > Timeline**: the plot has a *Pointing and propulsion load* line and the report a table of the events. **Ctrl+Z** undoes each change. (Manual.)
- [ ] **IDM-CIC import** (2.4.0): with a model file of your own (the tool ships none), **File > Import IDM-CIC model...**: pick the file, **Create a new project**, a folder and a bus voltage; the summary lists the units, modes and the findings and **No** writes nothing; **Yes** opens the new project and *Validate* shows no error. The **Mass** page shows a centre of gravity for the satellite and lists the units without one; compare it with the value IDM-CIC shows for your model. Import the same model again into the open project: *Nothing to write*. Change a mass in the model, import again: that one value changes, a value you edited in the Units grid stays.
- [ ] **Thermal against the beta angle** (2.7.0, command line): in a terminal, `budget thermal-beta` on the 250 kg example with `--beta-step 30 --out <folder>`: the table prints seven beta angles with hottest and coldest node, the folder holds `thermal_beta_hot_average` and `thermal_beta_hot_peak` as .csv, .json and .png (the plot shows the node temperatures and the sunlit part of the orbit against the beta angle).
- [ ] **Beta sweep page and spreadsheet tables** (2.8.0): open the 250 kg example. **Thermal > Beta sweep**: set *to* 90, *step* 30, **Compute**: the plot shows the node temperatures and the sunlit part of the orbit against the beta angle, the table has seven rows, **Export…** writes four files; changing *Heat loads* greys **Export…** until you compute again. **File > Export tables > Margin policy…** writes a .csv; fill a `margin_ratio` and its `source` for `class_a` / `mass_margin_ratio`, **File > Import tables > Margin policy…** shows the change, **Yes** writes it and the project reloads.
- [ ] **Explain for the beta sweep, the clean example and the IDM-CIC import** (2.9.0): on the **Beta sweep** page, compute, right-click a node's temperature: the Explain panel shows the exposure of each surface and the heat balance, and the solar view in it says *result of step 1*. In a terminal: `budget thermal-beta demo/microsat_250kg_clean --altitude-km 550 --mode average --at 30 --explain "EPS (K)"`. Open `demo/microsat_250kg_clean` (or *File > New project (guided)* with the sample *every input filled in*): the Problems panel shows no warning and no error, and **Run** on the Power timeline shows no violation. Import an IDM-CIC model that has equipment without a mapping in some system mode (*File > Import IDM-CIC model*): the plan shows one `IDM_POWER_UNMAPPED` warning for each system mode and no `UNIT_NOT_MAPPED` error after the project is written.
- [ ] **IDM-CIC components** (2.10.0): import your own IDM-CIC model (*File > Import IDM-CIC model*). The plan lists *Components* with a proposal for each battery, solar array, wheel, thruster, antenna... (by the id in the model, with a reason and *high* or *medium*); confirm. The project has `config/pointing.yaml`, `config/propulsion.yaml` and `config/power_system.yaml` with placeholders (n/a results, not errors) and a commented `idm/components.yaml`. Enter a wheel's torque in the library with a source, import the same model again: the value arrives in `pointing.yaml`; change a value in `pointing.yaml` by hand and import again: your value stays. Count how many of your equipment the proposals missed or got wrong (tell me their names).
- [ ] **Explain for propulsion and pointing, links as a spreadsheet** (2.11.0): open the 250 kg example, **Model > Propulsion** and **Pointing**: right-click a cell (a *Mass before (kg)* of a manoeuvre, a *Slew time (s)*) or Ctrl+Shift+I: the Explain panel shows the steps with their equations and the inputs with their sources. In a terminal: `budget explain <project> pointing:slews --row <slew> --column "Slew time (s)"`. **File > Export tables > Links…** to a .xlsx, open it in a spreadsheet program, change `transmitter.power_w` of one link and give a source, save, **File > Import tables > Links…**: the preview shows the change, **Yes** writes `links/<id>.yaml` and the comments of the file are still there; the same change without a source is refused. (Manual.)
- [ ] **Pillow 13 and the download checks** (2.11.2): open the PDF report and the plot PNGs of `microsat_250kg_eps` made by the installed program; the plots look as in 2.11.1 (Pillow went from 12.3 to 13.0). Run `python scripts/verify_offline.py --gui "$(which system-budget-studio)"` on Rocky 9 with `strace` installed: every step ok, 0 internet calls.
- [ ] **Diagnostics and the icons** (2.11.1): on a clean Windows machine, start the installed program from PowerShell: `.\system-budget-studio.exe --diagnose diag.txt` prints and writes the report (check *Icon loads: yes*, *Bundled font families registered* names Inter and JetBrains Mono, and that *Assets folder* is inside the install folder), then start `.\system-budget-studio.exe --fault-log crash.txt` normally: the window opens, **the navigation rail shows its icons** (it did not in a screenshot of 2.11.0), the window stays open for a minute when left alone, and `crash.txt` is empty after you close it. - [ ] **Run** (Ctrl+R): the bar and the step name appear; **Cancel** keeps the earlier results; a second **Run** completes. ## Licences and integrity (all platforms)

- [ ] The program folder contains `licences/` (with `COMPONENTS.json`), `licences.md`, `THIRD_PARTY_NOTICES.txt` and `sbom.cdx.json`; the SBOM lists what the bundle contains (the tool's runtime packages, Qt, the libraries copied from the build machine, the Python runtime, the bootloader, fonts, icons), no test or build tools. (CI: `packaging/check_bundle.py`, the licence gate.)
- [ ] **Help > Third-party licences** opens the notices; **Help > About** names the owner statement and the Apache License 2.0. (Manual; a window test checks both with a file.)
- [ ] **The trimmed Qt (D-261) on real desktops:** on Windows 10 and 11, on a Linux desktop with X11 and one with Wayland (Ubuntu, Rocky), start the window; **View > Theme > Same as the system** follows the system's light and dark setting while the window is open; the window has its frame and title bar; typing, the Ctrl+K palette and a file dialog work. If a function is missing, name the Qt plugin and put it back in `packaging/bundle_policy.toml`. (Manual.)
- [ ] The release has the source archives of Qt and PySide6 (`qtbase-everywhere-src-…`, `qtwayland-everywhere-src-…`, `pyside-setup-everywhere-src-…`, `SOURCES.txt`), one SBOM, one licence list and one notices file per system. (Manual; the release job checks that the sources exist.)
- [ ] The checksum of each download matches the list in `SHA256SUMS-windows.txt` (Windows files) or `SHA256SUMS-linux.txt` (the tarball, the `.deb` and the `.rpm`) on the Releases page. (Manual.)
- [ ] `system-budget-studio --smoke` exits with success on a machine with a display and, with `QT_QPA_PLATFORM=offscreen`, without one. (CI: all three platforms.)
